Concepts

sinks
env:svc#VAR (fichier .env par service) · file:/chemin · linux:user[@host] (chpasswd) · mysql:user@conteneur (ALTER USER) · cmd:… ({value} = nouvelle valeur, {AUTRE} = autre secret).
groupes
auto = roté par défaut · app / careful = roté explicitement · manual = jamais généré (posé à la main).
computed
Secret dérivé d'autres (ex. AUTHSF_DATABASE_URL, qui contient MARIADB_APP_PASSWORD) — se recalcule tout seul.
recréation
Un conteneur ne relit son env_file qu'à la création : tout service ciblé par un sink env: est donc recréé après application. Déduit des sinks, jamais déclaré à la main.
probe
Commande de vérification déclarée par secret (doctor) : teste la valeur contre la vraie app, exit 0 = ✓. Jamais destructif, n'affiche aucune valeur.
worker
Le seul composant privilégié (docker + store rw). Le dashboard n'a aucun privilège : il dépose un job dans le spool, le worker l'exécute et renvoie un log sans valeur.
accès
La carte Accès édite access/access.conf (source unique « qui voit quoi ») ; le worker relance render-access.py puis recrée Caddy et les homepages.
